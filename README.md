# Лабораторная работа: Настройка CI/CD конвейера

## Цель

Настроить автоматический запуск интеграционных тестов при каждом изменении кода с использованием GitHub Actions.

## Описание проекта

Проект состоит из двух условных микросервисов:

1. **UserService**: Хранит данные пользователей.
2. **OrderService**: Создает заказы, запрашивая данные пользователя у UserService через HTTP.

Так как запускать два отдельных сервера в рамках одного короткого цикла CI сложно, взаимодействие эмулируется через патчинг методов (`unittest.mock.patch`). Это позволяет проверять логику интеграции (обработку ошибок сети, таймауты, успешные ответы) без поднятия реальной инфраструктуры.

## Архитектура тестирования

Использован метод **интеграционного тестирования**. Тесты проверяют связку между слоем бизнес-логики заказа и слоем доступа к данным пользователя (внешнему сервису).


## Выводы

Метод CI/CD позволил автоматизировать проверку качества кода. Теперь любая ошибка в логике взаимодействия сервисов немедленно обнаруживается после коммита, что снижает риск попадания багов в основную ветку разработки. Использование моков вместо реальных сетевых вызовов сделало тесты быстрыми и стабильными в условиях ограниченных ресурсов CI-сервера.
